# ProofCheck 1.1 — تشغيله كموقع عام يعمل طوال اليوم

**النتيجة:** الحزمة تحتوي على تطبيق ويب بخادم Python وقاعدة بيانات SQLite، وواجهة عربية متجاوبة، وفحوصات تنفّذ في متصفح **الزائر نفسه**. أي شخص يستطيع فتح رابط الموقع بعد نشره على استضافة HTTPS، والبدء دون تثبيت برنامج. تحتاج فقط إلى رفع الحزمة إلى الاستضافة؛ **الملف المضغوط ليس عنوان موقع جاهزًا بعد**.

## الخيار الأسهل: Render (عنوان HTTPS تلقائي)

هذا الإعداد مناسب للتجربة الواقعية والمشروعات الصغيرة ذات **خادم واحد**. تحتاج حساب GitHub وRender، وخدمة **مدفوعة** بها قرص دائم؛ لا تستخدم استضافة مجانية تنام أو تمسح الملفات بين عمليات إعادة التشغيل.

1. فك الضغط عن ZIP.
2. أنشئ مستودعًا جديدًا على GitHub. ارفع **محتويات** مجلد `ProofCheck_Public_Ready` مباشرة إلى جذر المستودع، وليس مجلدًا داخليًا إضافيًا. لا ترفع `.env` أو قواعد البيانات.
3. انتقل إلى [Render Dashboard](https://dashboard.render.com) واختر **New → Blueprint**، ثم اربط مستودع GitHub.
4. سيتعرف Render على `render.yaml`: تطبيق Python، خطة مدفوعة صغيرة، قرص بيانات دائم 10GB، واختبار صحة `/api/status`. راجع **التكلفة الشهرية** قبل الموافقة على الإنشاء.
5. عند اكتمال النشر سيظهر لك رابط مشابه لـ `https://proofcheck-public-xxxx.onrender.com` (هذا **مثال**، وليس رابطًا فعليًا).
6. افتح عنوانك الجديد من جوال آخر وعلى شبكة مختلفة، وتأكد من ظهور واجهة ProofCheck ثم امنح موافقة الحفظ وابدأ اختبار الكاميرا/اللمس. رابط التقرير الذي تنشئه سيكون عامًا للقراءة فقط حسب مدة صلاحيته.
7. إذا كان لديك نطاق، يمكنك إضافته لاحقًا من إعدادات خدمة Render.

> أقراص Render الدائمة تحفظ قاعدة البيانات عبر إعادة النشر (ما عدا مشاكل خارج سيطرة التطبيق). وجود قرص دائم يمنع عادةً استخدام أكثر من نسخة واحدة من التطبيق مع نفس القرص، وقد تحدث فترات انقطاع قصيرة عند النشر. لا يوجد ضمان 100% للتوافر.

## بديل: خادم Linux خاص بك (VPS) + نطاق

1. ثبّت Docker مع Compose plugin على خادم بإنترنت مستمر.
2. سجّل DNS نوع `A` لنطاقك مثل `check.example.com` بعنوان IP العام للخادم، وافتح المنافذ `80` و`443`.
3. انسخ الملفات إلى الخادم، نفّذ `cp .env.example .env` ثم ضع اسم نطاقك الحقيقي في `PROOFCHECK_DOMAIN=`.
4. من داخل المجلد نفسه شغّل:

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f app
```

5. افتح `https://check.example.com/api/status` ثم افتح `https://check.example.com` وأجرِ فحصًا تجريبيًا من جهاز ثانٍ. يقوم Caddy بإعداد وتجديد TLS عندما تكون إعدادات DNS والشبكة صحيحة.
6. خصص آلية مراقبة للخدمة والقرص واستعادة بعد الأعطال، واحتفظ بنسخ احتياطية مستقلة ومشفرة من قاعدة البيانات.

### نسخة Windows المحلية (للفحص الأكثر قربًا للعتاد)

إذا شغّلت `start_windows.bat` سيعمل البرنامج **محليًا** على `http://127.0.0.1:8765` ويمكنه طلب معلومات الكمبيوتر واختبارات نظام التشغيل القصيرة. **هذا الرابط لا يعمل للآخرين عبر الإنترنت**، ولا تتوفر هذه المعلومات الأصلية من متصفح المستخدم البعيد لأسباب أمنية. يمكنك إتاحة نسخة الويب العامة مع الإبقاء على نسخة Windows المحلية منفصلة.

## ما الذي يحدث عندما يفتح زائر الموقع؟

1. تظهر موافقة واضحة قبل إنشاء الجلسة وتخزين معلوماتها في الخادم.
2. يحصل على جلسة خاصة برمز عشوائي قوي (رمزها **يعطي حق القراءة والتعديل والحذف**، فلا يجب نشره).
3. يجري اختبارات الألوان، اللمس، الكاميرا، الميكروفون، السماعات، لوحة المفاتيح وغيرها بحسب دعم متصفحه.
4. يستطيع تشغيل **قياسات متصفح** للمعالج (JavaScript)، والذاكرة (8MiB)، وتخزين IndexedDB (2MiB). تتم على جهاز الزائر وليس على خادم ProofCheck؛ ترسل للخادم تفاصيل النتيجة عند حفظها فقط. هذه **اختبارات قدرة/استجابة محدودة وليست كشفًا لأعطال المعالج أو RAM أو SSD**.
5. يضيف معلومات الجهاز والإصلاحات وصور/فواتير الأدلة، ويحفظ النتائج أو يصدر JSON وPDF من المتصفح.
6. يمكنه إنشاء رابط تقرير اختياري للقراءة فقط، صالح من يوم إلى 30 يومًا؛ مع حجب الرقم التسلسلي وبيانات البائع ومعلومات المتصفح وعدم نشر ملفات الأدلة نفسها. يمكن إلغاء الرابط أو حذف الجلسة.

## حدود مهمة قبل مشاركة الرابط للجمهور

- لا يمكن لموقع ويب عادي قراءة الأرقام التسلسلية لجميع مكوّنات الجوال أو إثبات أن الشاشة/البطارية أصلية أو أنها لم تُستبدل. iOS وAndroid وWindows وmacOS تفرض حدودًا مختلفة؛ غالبًا يلزم تطبيق أصلي مدعوم من الشركة أو فحص فني.
- الكاميرا والميكروفون يحتاجان موافقة المستخدم، وعادة اتصال HTTPS. قد يمنع بعض المتصفحات القياسات أو التخزين المؤقت أو الاهتزاز.
- لا يوجد نظام حسابات بكلمة مرور حتى الآن. **رمز الجلسة الخاص بمن يملكه، وهو بمثابة كلمة سر**. لا تستخدم الخدمة لجمع أسرار العملاء دون ترتيبات حماية إضافية.
- هذه البنية مناسبة للانطلاق واختبار عدد محدود من المستخدمين؛ قبل الاستخدام التجاري واسع النطاق يلزم **حسابات وتوثيق دخول، سياسات استخدام وخصوصية، مراقبة وحماية ضد الإساءة، نسخ احتياطية مشفرة دورية، وربما ترحيل SQLite إلى PostgreSQL والملفات إلى تخزين كائنات**.
- الاستضافة لها رسوم ويعتمد استمرار عمل الموقع على الخادم والمنصة والتجديد. إعدادات المشروع لا تنشئ حساب استضافة ولا تشتري نطاقًا ولا تفعّل خدمة مدفوعة تلقائيًا.

## اختبارات التشغيل

من داخل المجلد:

```bash
python -m unittest discover -s tests -v
python server.py --mode web --host 127.0.0.1 --port 8765 --no-browser
```

افتح `http://127.0.0.1:8765/api/status`، وتوقع قيمة `"mode":"web"`. افتح الموقع على نفس الكمبيوتر لتجربة الواجهة، ثم انشره عبر HTTPS لتجربته على الآخرين. فحوصات الويب لا تحتاج أن يشغّل المستخدم Python على جهازه بعد نشر الخادم.

**تنبيه للنسخ الاحتياطية:** `python tools/backup_db.py /path/to/proofcheck-backup.sqlite3` بعد ضبط متغير `PROOFCHECK_DB` على قاعدة البيانات الفعلية. يحتوي الملف على بيانات الأجهزة وربما الفواتير والصور؛ خزنه مشفرًا ولا تنشره.

### اختبار متصفح حقيقي بعد النشر (اختياري)

على كمبيوتر يسمح بتشغيل Chromium، ثبّت `pip install playwright` ثم `playwright install chromium`، وشغّل `python tools/browser_smoke.py https://YOUR_DOMAIN/`. ينشئ الاختبار جلسة مؤقتة ثم يحذفها، ويتحقق من موافقة التخزين والجلسة والقياسات ورابط التقرير. لم يعمل اختبار المتصفح هنا بسبب سياسة بيئة التنفيذ، ولذلك يبقى هذا التحقق مطلوبًا بعد النشر.
